# Packaging, updates, and fuses

## Toolchain choice

- **Electron Forge** (official, forge.electronjs.org): v7.x stable,
 v8 in alpha on `next`. Makers: squirrel.windows, wix/MSI, zip, dmg,
 deb, rpm, flatpak, snap, msix. Publishers: GitHub, S3, Nucleus,
 GCS. Absorbs @electron/packager, osx-sign, notarize, rebuild,
 fuses.
- **electron-builder** (community, electron-userland): v27, most
 downloaded, broadest targets - nsis, nsis-web, portable, AppX, MSI,
 Squirrel.Windows, dmg/pkg/mas, AppImage/snap/deb/rpm/pacman/apk,
 MSIX beta. Native ESM, needs Node >= 22.12.
- **@electron/packager**: the low-level bundler Forge wraps. Fine
 standalone but most users should go through Forge or builder.
- **asar**: app code packs into app.asar, unpacked exceptions via
 `asarUnpack`. Always pair with the embeddedAsarIntegrityValidation
 fuse.
- **macOS universal**: @electron/universal makeUniversalApp() glues
 x64 + arm64 into one .app. Both Forge and builder support the
 `universal` target natively.
- **MSI/enterprise**: Forge maker-wix or builder `msi` target,
 per-machine installs for SCCM/Intune. MSIX via @electron-forge/
 maker-msix or builder MSIX target - always runFullTrust, never
 AppContainer.

## Updates

**Built-in autoUpdater** (`electron`):
- macOS: Squirrel.Mac, needs a server returning update JSON or static
 releases.json, app must be signed. Delta entries supported
 (Sparkle BinaryDelta patches).
- Windows: Squirrel.Windows (for Forge/winstaller installs, reads the
 RELEASES file + .nupkg deltas) or the MSIX updater (E41+, detected
 via process.windowsStore).
- Linux: nothing built in.

**electron-updater** (from `electron-updater`, two-line swap):
- NSIS, AppImage, deb, rpm, pacman, mac zip. Squirrel.Windows is
 explicitly unsupported - use NSIS.
- latest.yml / latest-mac.yml / latest-linux.yml generated by
 electron-builder publish.
- Differential downloads for NSIS, AppImage, mac zip.
- Staged rollouts: `stagingPercentage` in latest.yml plus
 `isUserWithinRollout`.
- Channels: `channel` property selects which latest-*.yml is read.
- Providers: GitHub Releases, S3, generic HTTPS, Keygen.
- Signature verification on Windows and macOS.

**Update servers**: update.electronjs.org (free official OSS service,
public repo + GitHub Releases + code signing) paired with
update-electron-app. Self-host: Hazel, Nuts (private repos,
channels), electron-release-server (dashboard, non-GitHub sources),
Nucleus (multi-app), or plain static hosting of the manifests.

## Signing and notarization

- Windows: Authenticode via signtool. EV/HSM historically needed to
 skip SmartScreen. Azure Trusted Signing (~$120/yr) is now the
 modern path - electron-builder `azureSignOptions`, Forge via
 @electron/windows-sign >= 1.2.2 and AZURE_* env vars.
- macOS: Developer ID cert + notarization mandatory for non-Store
 distribution. @electron/notarize wraps notarytool. Hardened runtime
 plus com.apple.security.cs.allow-jit entitlement. Do NOT add
 allow-unsigned-executable-memory on Electron 12+.
- MSIX: must be signed. Trusted Signing works. Store submissions get
 signed by Microsoft.

## Fuses (@electron/fuses)

Post-build bit flips inside the binary:

- RunAsNode (ELECTRON_RUN_AS_NODE) - off in shipped apps.
- EnableCookieEncryption - OS-key-encrypted cookie store, one-way.
- EnableNodeOptionsEnvironmentVariable / EnableNodeCliInspectArguments -
  off in shipped apps.
- EnableEmbeddedAsarIntegrityValidation - on (macOS + Windows).
- OnlyLoadAppFromAsar - on.
- LoadBrowserProcessSpecificV8Snapshot, GrantFileProtocolExtraPrivileges,
  WasmTrapHandlers (E41+).

Set `strictlyRequireAllFuses: true` so upgrades fail loudly when a
new fuse appears unconfigured. `resetAdHocDarwinSignature` re-signs
arm64 mac binaries after flipping.
